## Agent Architecture

**Claude = manager.** Runs via Anthropic tool_use. Its tool is `send_to_gemini(message)`. Claude orchestrates the extraction, reviews results for logical consistency, and generates the final proposal.

**Gemini = visual extraction sub-agent.** Called by Claude via `send_to_gemini`. During Phase 3, Gemini runs its own inner tool loop (enhance_region, index_read, index_write, web_search). The full Claude↔Gemini exchange is visible in a sub-chat panel — read-only to the user.

**Two Gemini sessions:**
- **Phase 1:** N independent single-pass calls (one per page), with explicit prompt caching. Returns classifications + bboxes + importance flag per page.
- **Phase 3:** One continuous multi-turn Gemini conversation managed by Claude. Gemini starts with the Phase 1 text index (no images), pulls images on demand via `enhance_region`.

## Full Pipeline

```
1. FILE INTAKE
   Brian uploads PDF/image via existing /api/upload endpoint.
   Backend resolves file path from upload_id.
   PDF → render all pages to JPEG at adaptive DPI using fitz (pymupdf).
   Pages saved to: data/quick_proposal_runs/{run_id}/pages/page_NNNN.jpg
   SSE: emit page_ready events as each page renders → sidebar populates live.

2. INDEX INIT (Python only, no LLM)
   Load knowledge_pack.json from source pipeline.
   Load all 12 case library JSONs from source pipeline.
   Filter case library to selected_jobs from Brian's form.
   ChatIndex is initialized with pages + static knowledge data.
   SSE: emit index_loaded with job names → job selector checkboxes render.

3. PHASE 1 — BATCH CLASSIFICATION (Gemini, N independent calls)
   For each page image:
     Send: one page image + gemini_phase1.txt prompt (explicitly cached)
     Receive: JSON with classification, importance flag, bounding boxes
     Store in index: PageRecord + BboxRecords
     SSE: emit bbox_data → sidebar draws overlays on that page thumbnail
   Importance flag: "high" | "medium" | "low" — used in Phase 3 to prioritize.
   Phase 1 produces a text map of the plan; no metric extraction yet.

4. PHASE 2 — INDEX CONSTRUCTION (Python only)
   Parse all Phase 1 results into structured BboxRecords in the index.
   Index is now fully populated with spatial data.
   No LLM calls.

5. PHASE 3 — CLAUDE MANAGES GEMINI EXTRACTION (continuous loop)
   Claude receives: full Phase 1 JSON (text only, no images) + knowledge pack + case library.
   Claude opens the Phase 3 Gemini conversation via send_to_gemini.
   
   Gemini's initial context: Phase 1 classifications + bbox descriptions + importance flags.
   Gemini does NOT receive images upfront — it calls enhance_region to pull specific regions.
   
   Gemini inner tool loop:
     enhance_region(bbox_id, dpi=300) → renders crop from SOURCE PDF at dpi,
                                         returns inline base64 image in tool result.
                                         ALWAYS renders from original source, never
                                         from a pre-rendered thumbnail.
     index_read(key)  → read value from ChatIndex
     index_write(key, value, source_bbox_id) → write extracted value + provenance
     web_search(query) → search for standards/codes (existing app tool)
   
   Gemini writes each extracted value via index_write, recording the source bbox_id.
   This enables spatial deduplication: if two overlapping bboxes both contain road_LF,
   Gemini can call index_read to see the existing value and reconcile.
   
   Claude reviews Gemini's extraction for logical consistency (e.g. watermain_LF > road_LF
   is impossible — Claude flags it and Gemini re-examines).
   Claude can call send_to_gemini multiple times to redirect or request re-examination.
   Loop ends when Claude is satisfied with extraction quality.
   
   SSE: every send_to_gemini call, every Gemini reply, every tool call + result
        streams to sub-chat panel in real time.
   SSE: index_update events fire as Gemini writes values → live index panel updates.

6. STAGE 2 — CLAUDE PROPOSAL GENERATION
   Claude generates the line-item budget using:
     - index.extracted_data (Phase 3 output)
     - knowledge_pack ($/unit rate distributions)
     - case_library (12 analog jobs, filtered to selected)
     - system_prompt.txt from source pipeline (unchanged)
   Uses extended thinking: THINKING_BUDGET=10000, max_tokens=64000.
   SSE: budget_token events stream token by token.
   SSE: thinking_token events stream Claude's thinking (shown in collapsible panel).
   SSE: budget_complete fires with final structured {line_items, total, confidence, reasoning}.

7. FOLLOW-UP CHAT
   After budget_complete, a chat input appears in the panel.
   Claude retains full context: index, conversation history, proposal.
   Claude can re-engage Gemini via send_to_gemini if a follow-up requires re-examination.
   Run state persists indefinitely (no cleanup).
```

from typing import Optional
import uuid

@dataclass

    idx: int

    importance: str           # "high" | "medium" | "low"
    description: str          # Gemini's plain-language description of the page
    bbox_ids: list[str]

@dataclass
class BboxRecord:
    id: str
    page_idx: int
    x1: float; y1: float; x2: float; y2: float  # normalized [0,1] relative to parent
    parent_id: Optional[str]   # None = page-level bbox
    depth: int                 # 0 = top-level, 1+ = enhanced sub-region
    description: str           # "title block" | "stationing labels" | "lot count table" | etc.
    confidence: Optional[float] = None
    extracted_value: Optional[str] = None  # written by index_write during Phase 3

@dataclass
class EnhancedImage:
    id: str
    source_bbox_id: str
    image_path: str            # data/quick_proposal_runs/{run_id}/enhanced/{id}.jpg
    dpi: int
    child_bbox_ids: list[str] = field(default_factory=list)

@dataclass
class ChatIndex:
    run_id: str
    source_path: str = ""      # resolved path to uploaded file
    source_is_pdf: bool = True
    pages: list[PageRecord] = field(default_factory=list)
    bboxes: dict[str, BboxRecord] = field(default_factory=dict)
    enhanced_images: dict[str, EnhancedImage] = field(default_factory=dict)
    knowledge_pack: dict = field(default_factory=dict)
    case_library: list[dict] = field(default_factory=list)
    web_cache: dict[str, str] = field(default_factory=dict)
    extracted_values: dict[str, dict] = field(default_factory=dict)  # key → {value, source_bbox_id}
    extracted_data: dict = field(default_factory=dict)               # final aggregated extraction JSON

## The Tools

### `enhance_region`
```python
# src/quick_proposal/tools/enhance.py
import fitz  # pymupdf — in requirements-optional.txt, must be installed

def resolve_to_page_coords(index, bbox_id):
    """Walk parent chain → page-space normalized [0,1] coords."""
    b = index.bboxes[bbox_id]
    x1, y1, x2, y2 = b.x1, b.y1, b.x2, b.y2
    while b.parent_id:
        p = index.bboxes[b.parent_id]
        pw, ph = p.x2 - p.x1, p.y2 - p.y1
        x1 = p.x1 + x1 * pw;  y1 = p.y1 + y1 * ph
        x2 = p.x1 + x2 * pw;  y2 = p.y1 + y2 * ph
        b = p
    return x1, y1, x2, y2

def enhance_region(index, bbox_id: str, dpi: int = 300) -> bytes:
    """
    Crop source PDF at given dpi, return raw JPEG bytes for inline tool result.
    ALWAYS renders from index.source_path — never from a pre-rendered thumbnail.
    """
    x1, y1, x2, y2 = resolve_to_page_coords(index, bbox_id)
    b = index.bboxes[bbox_id]
    doc = fitz.open(index.source_path)
    page = doc[b.page_idx]
    pw, ph = page.rect.width, page.rect.height  # PDF points (72pt = 1 inch)
    clip = fitz.Rect(x1*pw, y1*ph, x2*pw, y2*ph)
    pix = page.get_pixmap(matrix=fitz.Matrix(dpi/72, dpi/72), clip=clip)
    doc.close()
    return pix.tobytes("jpeg")  # returns bytes, caller saves + serves
```

`enhance_region` tool result to Gemini must include the image as inline base64 data, not just a file path. The google-genai SDK supports `types.Part(inline_data=types.Blob(mime_type="image/jpeg", data=jpeg_bytes))` in function response content.

### `index_read` / `index_write`
Simple reads/writes on `index.extracted_values`. `index_write` records `source_bbox_id` alongside the value for provenance and deduplication.

### `web_search`
Reuse the existing Odysseus web search tool. Already implemented in the app.

## Upload Path Resolution

Brian uploads via the existing file upload UI (same as attaching a file in chat). This gives an `upload_id`. To resolve it to a file path on disk, mirror the logic in `routes/upload_routes.py → _resolve_upload_path()`:

```python
from src.constants import UPLOAD_DIR

def resolve_upload_path(upload_id: str) -> str:
    direct = os.path.join(UPLOAD_DIR, upload_id)
    if os.path.isfile(direct):
        return direct
    for root, _, files in os.walk(UPLOAD_DIR):
        if upload_id in files:
            return os.path.join(root, upload_id)
    raise FileNotFoundError(f"Upload {upload_id} not found")
```
